# Builder and summary polish — 2026-10-04

Implemented on `codex/payment-foundation`, following the local UI audit.
The owner approved committing, pushing and publishing these changes to a Vercel Preview for phone review on 2026-10-04. Production and `main` remain outside this publication scope.

## Changes

- Ingredient artwork: 38px → 64px, retaining the existing illustrated WebP assets.
- Names: 10.5px → 13px, with space for multiline Hebrew labels.
- Information remains a separate 44×44 button. The card footer reserves distinct space for its target and the surcharge.
- Surcharges stay on one line. Numeric direction is isolated with `bdi`, not applied to the logically positioned RTL badge.
- Information hint is smaller and dismissible. Hover lift is limited to fine pointers; selection artwork respects reduced motion.
- BariMeter has larger calorie figures, full macro labels, explicit Hebrew units, accessible groups and stronger contrast.
- The decorative full meter was removed: it was not a calculated health score.
- Nutrition assumptions remain unchanged. The typical-portion disclaimer is now readable below the artwork.
- Preparation instructions are listed separately rather than depicted as edible ingredients. Full order selections, counts, nutrition inputs and server submission data remain intact.
- Short summary viewports compact brand decoration and the footer, retaining pickup, the primary action and all legal links. The redundant 110px scroll spacer is gone.
- Opt-in isolated build directory prevents UI verification from overwriting the existing `.next` server. Generated files are ignored by Git, ESLint and the normal TypeScript project.

## Local review

The new build is served at `http://localhost:3002/build?size=M`. The existing port 3001 server and its `.next` build were left untouched.

To reproduce the isolated build on Windows PowerShell:

```powershell
$env:BARIBALI_UI_PREVIEW = "1"
npm run build
npm run start -- --port 3002
```

Without this opt-in, the normal production build directory remains `.next`.
